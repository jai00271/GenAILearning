1. The evaluation beat — metric · data · pass/fail

Har GenAI change se pehle teen boxes bharo. Incomplete boxes = vibes marketing.

  1. Metric — kya number? Precision@k, Recall@k, F1@k, MRR, latency_p95… Primary ek rakho; secondary optional.
  2. Data — kaunsa frozen set? Versioned golden JSONL with id, question, relevant_ids. Prompt examples se leakage check.
  3. Pass / fail — ship gate explicit: e.g. Recall@3 ≥ 0.75 on this golden. “Almost” allow nahi.

Lab helpers: load_golden_jsonl, find_leakage, precision_at_k / recall_at_k / f1_at_k, mean_reciprocal_rank, cohens_kappa, mcnemar_contingency, paired_bootstrap_pvalue. Known-good copies checkpoints/app-304/ mein freeze hain taaki APP 305 learner ke broken starter pe depend na kare.

2. Golden sets — frozen questions, labeled relevance

Golden set = chhota, versioned list of eval questions with known relevant document ids. Lab format JSONL: har non-blank line ek object — id, question, relevant_ids (list; empty allowed). Blank lines skip; bad JSON / missing keys fail fast. normalize_text + find_leakage train/prompt examples aur eval questions ke beech normalized overlap flag karte hain — exact string match after lowercasing / punctuation strip (semantic near-dup detection labeled simplification; lab nahi karta).

Pitfall · leakage

Few-shot examples mein wahi sawaal paste kar dena jo golden pe hai = training on the test set. Accuracy “magically” badhegi; production pe tootegi. Har golden refresh pe find_leakage chalao.

Intuition · .NET / backend

Golden JSONL ≈ xUnit theory data + expected IDs. Leakage check ≈ ensuring your test fixtures are not copied into the production seed data used at runtime. Version the file in git; treat edits like contract changes.

3. Precision, Recall, F1 @ k

Ranked retrieval mein binary relevance assume karo: doc relevant hai ya nahi. Top-k cut pe:

  • Precision@k = (relevant hits in top k) / k. Denominator always k (IR convention) — even if system returned fewer docs.
  • Recall@k = (relevant hits in top k) / |relevant|. Empty relevant set → lab returns 0.0 (avoid div-by-zero).
  • F1@k = harmonic mean of P@k and R@k; both zero → 0.

High precision, low recall = top results clean but many gold docs missing. High recall, low precision = gold mil gaya lekin top-k mein junk bhi. Product choose karta hai kaunsa pain zyada mehnga hai.

Source · ranked retrieval eval

Manning, Raghavan, Schütze, Introduction to Information Retrieval — evaluation of ranked retrieval results explains Precision/Recall on retrieved sets and why averaging across queries matters (nlp.stanford.edu/IR-book/…). Lab formulas teaching-scale copies of those identities are — not a full TREC toolkit.

4. MRR & nDCG — ranking quality intuition

Reciprocal rank (RR) ek query ke liye: pehle relevant doc ka 1-indexed rank r ho to RR = 1/r; miss → 0. MRR = mean RR across queries. “Pehla sahi result kitni jaldi aata hai?” — support search / FAQ style tasks ke liye natural.

nDCG (normalized Discounted Cumulative Gain) graded relevance + position discount ka classic metric hai: upar wale ranks zyada weight, lower ranks discount. Yeh lab nDCG implement nahi karta — intuition yeh hai ke binary P/R/MRR se aage graded labels aur position-sensitive gains aate hain. Jab stakeholders “#3 pe bhi theek hai” vs “sirf #1 matter karta hai” argue karein, nDCG / DCG framing useful hai (IR book ranking eval chapter).

5. Confusion matrix — classification view

Jab task binary/multiclass prediction ho (severity ok vs escalate; intent label), confusion matrix rows = true class, columns = predicted (convention vary — always label axes). TP / FP / FN / TN se precision/recall nikalte hain. Retrieval P@k conceptually “top-k predictions” pe same TP/FP language reuse karti hai, lekin ranked list + multi-relevant docs se matrix 2×2 simple case se richer hoti hai.

6. Cohen’s kappa — agreement beyond chance

Do raters (ya human vs model labels) same labels pe kitna agree karte hain? Raw percent agreement chance se inflate ho sakta hai (dono mostly “not escalate” bolte rahein). Cohen’s κ = (po − pe) / (1 − pe), jahan po observed agreement, pe expected agreement under independent marginals. Lab edge case: agar 1 − pe = 0, return 1.0 jab po = 1 else 0.0.

Source · Cohen’s κ

scikit-learn’s cohen_kappa_score documents κ as agreement corrected for chance (scikit-learn.org/…/cohen_kappa_score). Lab implementation teaching-scale hai; production papers often call sklearn/scipy directly.

7. Significance — 71% → 74% ship-worthy hai kya?

Same 100 queries pe system A = 71 correct, system B = 74. Absolute +3 points. Slide pe “improved.” Engineering sawaal: kya yeh noise ho sakta hai?

McNemar (paired binary): sirf discordant items matter — b = A wrong, B right; c = A right, B wrong. Statistic (b − c)2 / (b + c) (lab: no continuity correction — labeled simplification) aur chi-square 1-df style p-value. Example lab construction: 68 both right, 23 both wrong, 3 A-only, 6 B-only → accuracies 71 vs 74, b=6, c=3. Concordant cells significance nahi badalte.

Paired bootstrap: per-item scores (0/1 correctness ya continuous) ke paired differences ko with-replacement resample; observed mean(B−A) ke against bootstrap deltas se one-sided / two-sided p intuition. Teaching helper — full BCa intervals nahi. Clear constant gain → chhota p; identical vectors → observed Δ ≈ 0 aur p chhota nahi hona chahiye.

Source · McNemar / paired tests

McNemar’s test on paired nominal data focuses on discordant cells (classic contingency framing; see e.g. Wikipedia’s overview of McNemar’s test — en.wikipedia.org/wiki/McNemar’s_test — and textbooks on categorical data). For GenAI online eval, also prefer paired designs over unpaired “two different traffic weeks” when you can.

Pitfall · p-hacking the demo

Golden pe 20 baar tweak karke ek baar p<0.05 dekhna = multiple comparisons. Beat pehle freeze karo; exploratory slices alag label karo. PROD 401 deeper production eval pe jaayega — yahan fundamentals.

8. How not to fool yourself

  • Train/test leakage — prompt examples ∩ eval questions (normalized).
  • Metric shopping — jo number badhta dikhe woh report; primary pehle declare.
  • Tiny N — 8 queries pe 12.5% swings normal hain; confidence intervals / paired tests.
  • Stale goldens — product badla, labels nahi; “regression” false alarm.
  • Unpaired A/B — alag weeks, alag traffic mix; paired jab possible.
  • Leaderboard cosplay — public bench pe overfit; internal golden + failure slices rakho.
Intuition

CI mein flaky test ko “retry until green” se hide karna = bootstrap ko seed ghuma-ghuma ke p<0.05 dhundhna. Discipline: pre-register metric/data/gate, phir measure, phir ship ya revert.

Self-check · formative only

1. Evaluation beat ke teen boxes kya hain?

Reveal answer

Metric (primary number + definition), Data (frozen golden / slice + leakage hygiene), Pass/fail (numeric gate before ship). Vibes box nahi hai.

2. P@k ka denominator hamesha k kyun hota hai?

Reveal answer

IR convention: aapne budget k slots ka liya. Agar system 2 hi docs return kare aur k=5, baaki slots “empty / non-relevant” treat — precision penalize hoti hai. Lab bhi yahi follow karta hai.

3. MRR kya measure karta hai, nDCG intuition kya add karti hai?

Reveal answer

MRR = mean of 1/rank of first relevant hit (miss → 0). nDCG graded relevance + position discount add karti hai — lower ranks discounted; useful jab partial credit / graded labels hon. Lab nDCG code nahi likhwata; intuition ke liye cite.

4. 71→74 pe McNemar kyun concordant cells ignore karti hai?

Reveal answer

Paired comparison mein jahan dono systems same (dono right ya dono wrong), relative win/loss evidence nahi milti. Discordant b aur c batate hain kaun kiss item pe jeeta. Lab example: b=6, c=3 with 71% vs 74%.

5. Golden leakage ka practical check kya hai?

Reveal answer

find_leakage(train_or_fewshot_texts, eval_questions) after normalize_text. Hit aaya to example hatao ya golden split — metric ko “cheat” mat karne do.
