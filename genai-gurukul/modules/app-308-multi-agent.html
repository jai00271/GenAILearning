1. Multi-agent kab worth it — aur kab tax

Single well-prompted agent tab jeet'ta hai jab: ek clear goal, shared tool surface, aur failures ek trajectory pe debug-able hain. Multi-agent tab sense banata hai jab roles genuinely conflict or specialize — alag permissions, alag context budgets, parallel fan-out with merge, ya human-in-the-loop gates per lane. “Teen personas in one prompt” multi-agent nahi hai; woh roleplay hai.

  • Worth complexity: ticket triage worker (PII-scoped tools) vs research worker (KB-only); parallel evidence gather + merge; explicit handoff contracts.
  • Not worth it (yet): same tools, same model, same prompt split across “agents” for blog aesthetics; no eval on trajectories; no allowlists.
  • Cost signal: hops × tokens × tool latency — APP 307 max-steps breaker yahan per-graph max_hops ban'ta hai.

2. LangGraph vs CrewAI — mental models, not religion

LangGraph (LangChain ecosystem) graphs pe soch'ta hai: nodes, state, conditional edges, checkpoints. Control-flow explicit hota hai — backend engineer ke liye state machine vibe. CrewAI roles + tasks + “crew” collaboration pe pitch karta hai — faster to sketch human org charts as agents. Dono perishable APIs hain (re-check docs August 2026+). Lab mein hum edges ko dict + functions se simulate karte hain taaki concept framework wheel ke bina clear rahe.

Shape When it helps Watch-outs
Graph (LangGraph-like) Explicit routes, cycles with halt, durable state Easy to over-node; debugging = reading the path
Crew / roles (CrewAI-like) Human-readable role split, task briefs Hidden orchestration; role sprawl without tool isolation
Single agent One goal, one catalog, one trajectory Context bloat if you fake multi-role in one prompt
Pitfall

“We use CrewAI/LangGraph” portfolio line empty hai bina: (1) edge diagram, (2) tool allowlists, (3) trajectory sample, (4) kab single agent enough tha. Framework name skill nahi hai — orchestration judgment skill hai.

3. MCP across agents — shared tool catalogs

Model Context Protocol tools ko server-side catalog banata hai: tools/list, tools/call, JSON Schema params. Multi-agent world mein sabse clean pattern: ek shared catalog, har agent ko allowlisted view. Duplicate handlers per agent = drift. APP 307 ka ToyMCPClient single loop ke liye tha; yahan SharedToolCatalog.allowlist(...) worker isolation sikhata hai — ticket worker search_kb nahi dekh'ta.

Production mein MCP servers process boundaries cross kar sakte hain; lab in-process hai. Idea same: catalog ownership central, permissions per agent, call results trajectory pe structured.

4. Framework lock-in — mandatory judgment call

Yeh section skip mat karna. Frameworks speed dete hain; woh your contracts bhi hide karte hain. Jaano kya abstract ho raha hai, phir decide karo own vs buy.

Lock-in lesson · own the seams

LangChain historically chains, tools, memory adapters abstract karta hai. LangGraph durable graph execution / state. LlamaIndex ingestion + index + query abstractions (APP 305). Use them when team velocity > custom control and aap tool catalog + eval hooks + policy boundaries bahar extract kar sakte ho. Raw OpenAI / Anthropic / Bedrock / Ollama SDK choose karo jab: streaming + cost accounting tumhari competitive edge hai, framework upgrades break prod, ya compliance ko thin dependency graph chahiye. “Never use frameworks” dogma utna hi kharab hai jitna “always LangChain”.

5. Eval hook — multi-agent trajectories

RAG metrics (P@k, R@k, MRR — APP 304) final answer quality ke liye zinda rehte hain jab retrieval involved ho. Deep agent-eval methodology PROD 401 mein; yahan habit yeh hai ke path log bina ship mat karo.

6. Portfolio-facing English — when multi-agent wins

Portfolio-facing English · Decision stub

Prefer a single agent with a shared tool catalog unless you can name a permission boundary, parallelism need, or context-budget split that a second agent uniquely provides. If you adopt LangGraph or CrewAI, keep tool descriptors, trajectory logging, and stop conditions outside the framework’s opaque defaults so you can swap runtimes without rewriting policy. Evaluate with merged trajectories plus any task-level quality metrics — not demos alone.

Self-check · formative only

1. Multi-agent kab overkill hai?

Reveal answer

Jab same tools + same model + same goal ko sirf personas mein split kiya, bina permission/parallelism/context reason ke — aur bina trajectory eval ke.

2. Shared MCP catalog ka point kya hai?

Reveal answer

Ek jagah tool contracts; agents ko allowlisted views. Drift aur accidental powerful-tool access kam.

3. Framework lock-in lesson — kya own karna hai?

Reveal answer

Tool catalog, trajectory/eval hooks, tenant/policy seams — even if LC/LGraph/LI scaffolding use karo. Raw SDK jab yeh seams product edge hon.

4. Multi-agent eval hook lab mein kya hai?

Reveal answer

Merged trajectory (seq-ordered) + per-agent/kind counts + tool names — RAG@k ke saath, uski jagah nahi jab retrieval matter kare.

5. LangGraph vs CrewAI one-line?

Reveal answer

Graph = explicit state/edges; Crew = role/task collaboration skin. Pick for the control story you need; measure hops and failures either way.
