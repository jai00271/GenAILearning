Neural Networks Primer

Track: FOUND Labs: genai-gurukul-labs/found-103/ Prereq: FOUND-102

Transformers se pehle ek baat clear kar lena useful hai: neural network koi magic black box nahi, balki stacked linear maps + nonlinearities ka programmable function approximator hai. LLMs usi idea ko bohot deep, bohot wide, aur attention-aware bana dete hain. Agar aapko neuron, layer, forward pass, aur “loss se weights update” ka engineer-level picture mil gaya, toh baad ke CORE modules mein attention diagrams itne alien nahi lagenge.

1. Neuron, ReLU, aur layer

Ek artificial neuron roughly yeh karta hai: inputs ka weighted sum lo, bias add karo, phir nonlinearity se guzaaro. Linear part: z = w·x + b. Nonlinearity ke bina kitni bhi layers stack kar lo, overall function ek hi badi linear map ban ke reh jaati hai — isliye activation zaroori hai. Modern default aksar ReLU: relu(z) = max(0, z). Positive signals pass; negative cut. Simple, fast, aur deep nets mein empirically strong.

Ek layer kai neurons ka parallel set hota hai. Matrix form mein: h = relu(x W + b) jahan W shape [in_dim, out_dim] (hum labs mein is convention ko follow karenge). “Hidden layer” ka matlab intermediate representation; “output layer” task ke hisaab se activation change kar sakti hai (regression mein sometimes linear).

Intuition

ReLU ko “switch” socho: kuch features off, kuch on. Deep stacks of switches sophisticated decision regions bana sakti hain — yeh capacity ka source hai, mystery ka nahi.

2. Forward pass

Forward pass matlab: input do, layers se left-to-right compute karo, prediction ŷ lo. Lab mein hum ek TinyMLP use karenge: input dim 2 → hidden dim 2 (ReLU) → output dim 1 (linear). Yeh itna chhota hai ki aap har number table pe trace kar sakte ho — debugging muscle ke liye ideal. 

# Conceptual shapes
x:  (2,)
W1: (2, 2), b1: (2,)
h = relu(x @ W1 + b1)      # (2,)
W2: (2, 1), b2: (1,)
y_hat = h @ W2 + b2        # (1,) / scalar
Hands-on

Lab mlp.py: TinyMLP.forward implement karo. Tests ek fixed weight fixture pe ŷ ≈ 0.17 expect karte hain — taaki aap speculative “almost right” pe na ruko.

3. Backward pass — chain rule intuition (no full derivation)

Loss L usually prediction aur target ke beech ka scalar hota hai. Regression demo ke liye MSE: L = (ŷ - y)² (kabhi 1/2 factor se gradients prettier bante hain; consistency matter karti hai). Backward pass poochta hai: ∂L/∂W kya hai? Chain rule ka engineer translation: “loss output pe kaise depend karti hai, output hidden pe, hidden weights pe — locally multiply the sensitivities.”

Full autograd engine banana is module ka goal nahi. Goal yeh hai ki aap believe karo ki har weight ke liye ek number exist karta hai jo kehta hai “mujhe thoda badhao toh loss up/down”. Lab mein numerical_dL_dW2 finite differences se estimate karega, aur train_step analytic gradient se update — dono roughly agree karein, toh aapka mental model sound hai.

Source

Goodfellow, Bengio & Courville — Deep Learning Book, Chapter 6 (Deep Feedforward Networks) — MLP, activations, capacity, aur backprop context ka standard reference chapter; FOUND-103 isi chapter ke engineer-facing subset ko operational banata hai.

Pitfall

Gradient ko “AI samajh” mat samajhna. Yeh local sensitivity hai. Saddle points, noisy batches, aur bad scaling aapko confuse kar sakte hain. Production deep learning mein tooling (autograd) pe trust + gradient checks debugging ke liye — vibes pe nahi.

4. Training loop

Minimal loop: (1) forward, (2) loss, (3) backward / grads, (4) weights −= lr * grads, (5) repeat. Epochs, shuffling, regularization — yeh sab us skeleton pe layers hain. TinyMLP pe aap literally dekoge ki MSE drop hoti hai jab lr sane ho. Agar loss explode kare, pehle lr aur initialization check karo, architecture philosophy nahi. 

for step in range(num_steps):
    y_hat = model.forward(x)
    loss = (y_hat - y) ** 2
    model.train_step(x, y, lr=0.1)  # uses analytic grads internally

5. Overfitting — engineer’s view

Overfitting tab hota hai jab model training set ke quirks memorize kar leta hai aur unseen data pe generalize nahi karta. Classic signs: train loss neeche, val loss upar; perfect train accuracy, fragile production behaviour. GenAI mein bhi related failure modes hain — prompt overfitting, eval-set contamination, retrieval corpora pe memorized answers.

Engineer toolkit (intuition level): zyada data / better data, regularization, early stopping, simpler model, augmentation, aur — LLMs ke context mein — held-out evals jo aap train prompts se leak na karein. Capacity khud enemy nahi; unchecked capacity + tiny noisy data enemy hai.

Recall

Layered affine + ReLU → forward ŷ. Loss se gradients. Update weights. Watch generalization, not only train loss. Next track (CORE) tokenization se language models ko discrete symbols pe operate karna sikhayega.
