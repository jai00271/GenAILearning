Recall · PROD 403 · 404 · 406

Indirect injection = retrieved docs as attacker surface (403). Cost blowup = soft-only budgets / tool loops / retry storms (404, Debug B). CI gate + sticky canary = how you change prompts/models without big-bang regret (406).

1. Challenge kya hai — aur kya nahi

Design a CI gate for a prompt or model candidate: name the offline quality metrics, the trace/cost signals, thresholds (max_drop / worsen), and the fail-closed annotation. Write a flag/canary plan: sticky key, percentage stages, what you watch at each stage, rollback trigger. Write an English memo (~400–600 words) that covers both indirect injection and cost blowup — controls, residual risk, how the gate/canary would catch regressions.

Yeh CAP 501 nahi hai. Yeh fine-tune nahi hai. Yeh “paste LaunchDarkly screenshot” nahi hai. Agar memo sirf injection cover kare aur cost skip kare — Production awareness pe fail. Agar gate thresholds vague hon — Evaluation evidence pe fail.

2. Kaise approach karo

Pehle system slice freeze karo (RAG agent? single-tool?). Phir baseline metrics naam do. Gate fail rules likho — including “eval flat / traces worse”. Canary stages + sticky key + rollback. Memo mein OWASP-flavored injection path aur unbounded consumption / agent cost path dono explicit.

3. Portfolio-facing English — deliverables

Portfolio-facing English · Memo requirements

Write a one-page memo (approximately 400–600 words) in clear English. Describe your CI eval gate (metrics, thresholds, fail-closed behavior, including trace/cost worsen when offline scores look flat). Describe your feature-flag / canary plan (sticky key, percentage stages, watchlist, rollback). Explicitly cover indirect prompt injection (retrieved documents as the attack surface; controls and residual risk) and cost blowup (unbounded tool loops, retry storms, hard ceilings, tenant attribution). End with reverse conditions: when you would freeze canaries, force rollback, or widen the gate.

4. Rubric — score yourself before CAP

Portfolio-facing English · Pass rule

Each dimension is scored from 1 to 4. You pass the PROD track challenge only when no dimension is below 2 and the average across the four dimensions is at least 3.0. Anything less means revise before treating CAP 501 as unlocked for yourself.

Dimension 1 — Inadequate 2 — Developing 3 — Solid 4 — Exemplary
Correctness / artifact Deliverables are missing, not in English, or omit the CI gate, canary/flag plan, or memo. Artifacts exist but are vague, incomplete, or contradict each other on thresholds or stages. A clear CI gate, staged flag/canary plan, and one-page English memo align on a coherent ship path. Artifacts are review-ready: concrete thresholds, sticky canary stages, rollback triggers, and memo that a staff eng would accept.
Evaluation evidence No named metrics, thresholds, or fail rules; vibes-only ship criteria. Some metrics named, but pass/fail rules, baseline freeze, or trace worsen handling are fuzzy. Offline quality metrics plus at least one trace/cost signal with explicit thresholds and fail-closed behavior. Evidence includes how flat-eval/worse-trace cases fail the gate and what would be re-measured after rollback.
Engineering judgment Big-bang cutover or flag-free deploy; ignores progressive delivery. Mentions canary superficially without sticky keys, stages, or rollback. Weighs staged rollout vs risk; sticky percentage plan with watchlist and rollback conditions. Judgment reads like production triage: default canary, explicit freeze/rollback, scoped next experiments.
Production awareness Ignores indirect injection or cost blowup entirely. Mentions one risk in passing without controls or residual risk. Addresses both indirect injection and cost blowup with controls tied to gate/canary monitoring. Treats both as deployable risks: detection signals, hard ceilings, tenant attribution, and residual risk named.
