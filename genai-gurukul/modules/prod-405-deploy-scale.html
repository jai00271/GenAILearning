TTFT green, total red — ek budget se dono nahi bachenge

Models 5xx / mid-stream hang karte hain — multi-provider failover + timeout chahiye. Shared vector stores pe tenant isolation bhoolna = data leak class incident. Scope (all first-class): TTFT vs total separate budgets; TPM capacity planning; model/provider failure modes + multi-provider failover + mid-stream timeout; tenant isolation in shared vector stores; rollback / degraded mode. Lab offline — no live keys.

Recall · APP 302 · CORE 201 · PROD 404

APP 302 ne streaming vs batch latency alag sochna sikhaya; CORE 201 TPM ko token reality se joda; PROD 404 ne retry storms + provider circuits. Yahan budgets, capacity math, aur failover router concrete karte hain.

1. TTFT vs total — alag budgets

Chat UI: pehla token late = “broken”. Summarization job: total wall time matter. Ek hi p95 number dono ko hide kar sakta hai — TTFT blow up, total still “ok”, ya ulat. Lab check_latency_budgets dono gates alag pass/fail karta hai (failed_budgets: ["ttft"] vs ["total"]).

2. TPM capacity planning

Rough demand: rpm × (avg_tokens_in + avg_tokens_out). Usable capacity: provider_tpm_limit × safety_factor (headroom for spikes / retries). Overshoot pe options: reduce tokens, queue/shed, raise limit, shard across keys / providers. Published TPM numbers change — OpenAI/Anthropic dashboards pe verify; lab fixtures didactic hain.

Source · Provider rate limits

OpenAI rate limits guide: platform.openai.com/docs/guides/rate-limits. Anthropic rate limits: docs.anthropic.com/en/api/rate-limits. Treat TPM/RPM as operational inputs, not forever constants.

3. Failure modes · failover · mid-stream timeout

Failure Symptom Mitigation
Hard 5xx / auth Immediate error Failover to next provider; open circuit after N fails
429 TPM/RPM Throttles + retry storm risk Backoff + jitter; shed; capacity plan (PROD 404 storm detector)
Mid-stream hang TTFT ok, tokens stall Mid-stream timeout → cancel → failover
Quality regress 200s but wrong Not a router problem — eval gate / rollback (406)

Lab route_with_failover: ordered providers, skip open circuits, treat total_ms > mid_stream_timeout_ms as timeout even if fixture claims ok=True.

4. Tenant isolation in shared vector stores

Shared index + missing tenant filter = cross-tenant retrieval (security incident, not “relevance bug”). Patterns: per-tenant collections/namespaces; mandatory metadata filter on every query; separate credentials; periodic access tests. APP 306 vector lessons pe yeh production constraint harden karo — deploy checklist item, optional feature nahi.

Source · OWASP LLM data risks

Cross-tenant leakage sits near sensitive-information and vector/RAG abuse themes in the OWASP LLM Top 10 — start from owasp.org/www-project-top-10-for-large-language-model-applications and your vector vendor’s multi-tenancy docs (e.g. metadata filtering / namespaces).

5. Rollback & degraded mode

Pre-declare: (1) pin previous model/prompt version; (2) degrade to smaller/local model or retrieval-only FAQ; (3) feature-flag kill switch (406). Without a degraded path, failover to “also down” peers sirf latency badhata hai. Combine with PROD 404 cost ceilings taaki degraded path bhi unbounded na ho.

Pitfall

Sirf total latency SLO. Streaming users TTFT pe churn karte hain. Doosra: failover without timeout. Teesra: shared vectors without tenant predicate.
