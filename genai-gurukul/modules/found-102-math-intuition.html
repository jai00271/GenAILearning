Math Intuition for LLMs

Track: FOUND Labs: genai-gurukul-labs/found-102/ Prereq: FOUND-101

LLMs ke papers mein jo symbols aate hain — vectors, softmax, log-probs, perplexity, gradients — woh intimidate isliye karte hain kyunki unhe pehle “exam math” ki tarah padhaaya jaata hai. Engineer ke liye zarurat alag hai: aapko proof olympiad nahi jeetna; aapko yeh feel chahiye ki number move hone pe model behaviour kaise move hota hai. Is chapter mein hum IT-shop analogies, worked numbers, aur production pitfalls ke through woh feel banayenge.

1. Vectors, dot product, cosine — IT wiki example

Socho aapke company ka internal wiki hai. Query: “VPN reset Windows”. Do candidate chunks hain. Chunk A VPN troubleshooting pe hai; Chunk B cafeteria menu pe. Embedding model dono chunks aur query ko vectors mein map karta hai. Ab ranking ka sawaal geometry ka sawaal ban jaata hai: kaunsa vector query ke direction ke zyada qareeb hai?

Dot product q·d = Σ qᵢ dᵢ un dimensions ko amplify karta hai jahan dono large same-sign values share karte hain. Agar query “VPN/network” dimensions pe strong hai aur cafeteria chunk un pe near-zero hai, dot chhota rahega. Cosine usi idea ko length-invariant banata hai — lamba document embedding magnitude se unfair boost na le. 

# Tiny 3-D toy (not a real embedding model)
q = [1.0, 0.8, 0.1]   # vpn, network, food
a = [0.9, 0.7, 0.0]   # VPN article
b = [0.1, 0.0, 0.9]   # cafeteria menu

# cosine(q,a) ≫ cosine(q,b)  → retrieve A

2. Softmax aur temperature — worked numbers

Language model next-token ke liye raw scores nikalta hai, jise hum logits kehte hain. Softmax un logits ko probability distribution mein badalta hai: har score ko exp mein daalo, phir sum se divide. Exp isliye taaki larger logits disproportionately dominate karein, aur saari probs positive + sum-to-one hon.

Temperature T logits ko divide karke sharpness control karti hai: softmax(z / T). T → 0 pe distribution almost argmax pe collapse; T = 1 default; T > 1 pe distribution flatter — zyada entropy, zyada surprise. Distillation literature mein temperature ko soft targets banane ke liye deliberately raise kiya jaata hai.

Worked example — teen tokens, logits z = [2.0, 1.0, 0.1]:

Tokenzexp(z) @T=1p @T=1exp(z/2) @T=2p @T=2
α2.07.3890.6592.7180.502
β1.02.7180.2421.6490.304
γ0.11.1050.0991.0510.194

Dekho: temperature 2 pe α ab bhi winner hai, lekin lead kam zor daar hai. Yeh exactly wahi knob hai jo chat UIs “creativity” ke naam pe expose karti hain — mathematically entropy knob.

Source

Hinton et al., Distilling the Knowledge in a Neural Network (arXiv:1503.02531) — Temperature ko soft probability targets ke liye raise karne ka classic reference; “softmax pe T” ka production intuition yahi paper popular karti hai.

3. Log-probabilities aur perplexity (full section)

Probabilities chhoti-chhoti numbers hoti hain — jaise 0.002. Unhe baar-baar multiply karoge toh floating underflow. Isliye systems log-probabilities (logprobs) prefer karti hain. Log domain mein multiply → add ban jaata hai: sequence logprob = sum of token logprobs. Negative log-likelihood (NLL) = -log p(token); average NLL ek sequence kitni “surprising” thi, uska scalar summary hai.

Perplexity (PPL) us average NLL ko human-friendlier scale pe laati hai: 

PPL = exp( mean_i [ -log p(token_i) ] )
    = exp( mean NLL )

Intuition: perplexity roughly “effective branching factor” hai. PPL = 10 ka matlab model, average token pe, aise behave karti hai jaise ~10 equally likely options mein se choose kar rahi ho. Lower PPL on a fixed evaluation corpus usually better next-token modeling indicate karti hai — lekin yeh automatically “better product” nahi hai. Chat helpfulness, safety, aur task metrics alag hote hain.

Worked table

Teen-token sequence, model probabilities 0.5, 0.25, 0.125 (natural log use karte hain labs mein, lekin koi bhi consistent base chalega — exp/log pair match hona chahiye):

iplog pNLL = -log p
10.500−0.6930.693
20.250−1.3861.386
30.125−2.0792.079

Mean NLL ≈ (0.693 + 1.386 + 2.079) / 3 ≈ 1.386. PPL = exp(1.386) ≈ 4.0. Nice round number isliye mila kyunki yeh geometric progression thi — debugging ke liye aise fixtures gold hote hain.

Source

Hugging Face — Perplexity of fixed-length models — Practical notes on computing perplexity with sliding windows / stride; reminds you that implementation details (how you chunk long text) PPL numbers ko materially change kar sakte hain.

Source

Jurafsky & Martin, Speech and Language Processing — Ch. 3 (N-gram Language Models) PDF — Classical definition: perplexity as normalized inverse probability of the test set; modern neural LMs same information-theoretic core share karte hain.

Source

OpenAI API — logprobs (docs as of Aug 2026) — Chat Completions request pe logprobs / top_logprobs flags se per-token log probabilities expose hote hain; evaluation harnesses isi pe build hote hain. (API surfaces evolve — integrate se pehle current docs verify karo.)

Production pitfalls

Pitfall

Comparing PPL across tokenizers is cheating. Alag BPE vocab → alag token boundaries → alag “per token” normalization. Hamesha same tokenizer + same preprocessing pe compare karo. Subword vs word-level reporting mix mat karo.

Pitfall

Teacher-forcing PPL ≠ generated quality. Teacher forcing gold prefix pe next-token score karti hai. Free-run generation mein errors compound hoti hain. Low PPL model bhi dull/unsafe chat de sakti hai; high-PPL domain shift pe bhi kabhi useful specialized behaviour dikh sakta hai.

Pitfall

Log base aur padding tokens. Mix of log/log2 without matching exp/2** se nonsense PPL milti hai. Pad/special tokens ko average mein include karna bhi metric ko artificially improve/worsen kar sakta hai — mask carefully.

4. Gradient descent — intuition only

Training ka core loop emotional language mein: model prediction galat hai, loss bataata hai “kitni galat”, gradients bataate hain “kaunse weights kis direction mein tweak karne se loss kam hoga”, optimizer chhota step us direction mein leta hai. Yeh mountain pe andhe utarne jaisa hai — aap globally best valley guarantee nahi karte, local improvement chase karte ho.

GenAI engineer ke liye practical takeaways: learning rate bahut bada → divergence/NaNs; bahut chhota → waste compute; batch composition loss landscape ko change karti hai; aur “loss gir gaya” ka matlab yeh nahi ki product metric jeet gayi. FOUND-103 mein hum ek tiny MLP pe yeh loop literally code karenge.

Recall

Cosine = direction match for retrieval. Softmax+T = distribution sharpness. Logprobs add; PPL = exp(mean NLL). Gradients = “which way reduces loss.”
