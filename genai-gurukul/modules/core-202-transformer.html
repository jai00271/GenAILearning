CORE 202 · The Transformer Architecture

Self-attention: har token har dusre token se seedha baat kare — bina RNN queue ke

Track: CORE Labs: genai-gurukul-labs/core-202/ Local NumPy · no paid API Prereq: CORE 201 + FOUND 102 softmax

CORE 201 ne text ko token ids mein todna sikhaya. Ab sawal yeh hai: un ids ke embedding vectors ko model kaise combine karta hai taaki “auth pod” aur “password reset” ek dusre ko dekh saken, chahe beech mein das tokens hon. 2017 se pehle dominant jawab recurrent networks tha — left-to-right (ya bidirectional) hidden state jo sequence ke saath chalta hai. Vaswani et al. ka Transformer us recurrence ko hata kar self-attention ko backbone banata hai: har position, parallel, sequence ki baaki positions se weighted mix nikalta hai. Yeh chapter us mechanism ko engineer language mein padhata hai — Q/K/V, multi-head, positional encoding, encoder vs decoder, aur woh honest list ki RNNs yahan kyun haar gayi.

Hum paper ka reproduction nahi likh rahe, aur backpropagation-through-attention ka full derivation nahi karenge. Jo aap lab mein implement karoge: scaled dot-product attention, causal (autoregressive) mask, aur ek chhota multi-head wrapper — NumPy mein, taaki baad mein jab APP 302 “KV cache” kahe, aapko pata ho cache kya store kar raha hai.

Recall · FOUND 102 / 103

Softmax probabilities banata hai; temperature usse pehle logits scale karti hai. Yahan attention scores bhi logits ki tarah behave karte hain — unhe softmax se weights banate hain, phir values ka weighted sum lete hain. FOUND 103 ka forward pass composition yahi hai: linear maps + nonlinearity (yahan softmax) + combine. Sirf shapes ab (seq, d) hain, (2,) nahi.

1. Problem RNNs solve nahi kar paayi at scale

Ek recurrent layer sequence ko step-by-step consume karti hai. Step t ka hidden state step t−1 par depend karta hai. Yeh dependency training ko inherently sequential banati hai: aap GPU par batch to bada kar sakte ho, lekin ek sequence ke andar ke timesteps ko freely parallelize nahi kar sakte. Lambi dependencies ke liye signal ko kai steps travel karna padta hai — vanishing / exploding gradients ka classic dard, plus wall-clock that grows with sequence length.

Self-attention ka contract alag hai: sequence ke saare positions ek dusre ko ek hi layer mein dekh sakte hain (modulo masking). Path length between any two tokens becomes constant rather than linear in sequence length. Cost badal jaata hai — attention matrices O(n²) in sequence length for the naive implementation — lekin modern hardware par yeh trade-off 2017 ke baad jeet-ta gaya, aur decoder-only Transformers (GPT lineage) industry default ban gaye. PROD 405 capacity planning mein yahi n² phir se dikhega jab aap context window double karoge.

Source

Ashish Vaswani et al., “Attention Is All You Need,” NeurIPS 2017 (arXiv:1706.03762), arxiv.org/abs/1706.03762. Paper introduce karti hai Transformer ko — pehla transduction model jo entirely attention mechanisms par based hai, recurrence aur convolutions ko dispense karke — aur dikhati hai ki yeh architecture zyada parallelizable hai aur significantly kam training time maangta hai compared to recurrent baselines on machine translation.

2. Scaled dot-product attention — Q, K, V

Teen matrices socho, same sequence se derived: Queries (Q), Keys (K), Values (V). Intuition — imperfect, lekin useful — ek retrieval system jaisi hai. Query poochta hai “mujhe kis tarah ki information chahiye?” Key har position ka label / index hai. Value woh payload hai jo aap actually mix karke aage bhejoge. Score between query position i aur key position j unke dot product se aata hai. Softmax across j weights banata hai. Output i = values ka weighted sum.

Formula, paper ke notation mein: Attention(Q, K, V) = softmax(QKᵀ / √dₖ) V. Yahan dₖ key/query dimension hai. Division by √dₖ scaling hai: bina iske, badi dimensions par dot products ke magnitude badh jaate hain, softmax saturation (FOUND 102 peaky distribution) gradients ko maar deti hai. Yeh “just a constant” nahi — numerically zaroori hai.

Self-attention ka matlab: Q, K, V same input sequence se linear projections hain (X W_Q, X W_K, X W_V). Har token doosre tokens ko attend karta hai, including (usually) itself. Cross-attention (encoder–decoder) mein Q ek side se, K/V doosri side se aate hain — translation-style models mein common; pure decoder-only LLMs mein self-attention + causal mask dominant pattern hai.

Intuition

Datadog mein aap ek trace ke spans ko related ids se join karte ho. Attention soft join hai: har query row poori key table par distribution rakhti hai, phir values aggregate karti hai. Analog toot-ta hai kyunki join keys yahan learned projections hain, schema columns nahi — aur weights continuous hain, foreign-key match nahi.

3. Multi-head attention — parallel subspaces

Ek hi attention head saari “reasons to look” ko average kar deta hai. Multi-head attention Q/K/V ko h alag projected subspaces mein bhejta hai, har head apna attention compute karta hai, outputs concatenate hote hain, phir ek output projection W_O se wapas d_model dimension mein aate hain. Paper ke original setup mein h = 8 aur dₖ = dᵥ = d_model / h = 64 tha — chhote heads ke saath total compute roughly single full-dimensional head jaisa rehta hai.

Practitioner reading: heads specialization sometimes interpretable hoti hai (syntax vs rare tokens), lekin aap production mein heads ko manually assign nahi karte. Aap capacity aur latency budget choose karte ho. Zyada heads / zyada d_model = zyada quality ceiling (often) aur mehnga forward pass. APP 302 quantization is matrix multiply wall ko chhupegI; pehle shapes clear rakho.

Source

Vaswani et al., §3.2.2 Multi-Head Attention (same paper as above). Authors state that they linearly project queries, keys, and values h times into smaller dimensions, run attention in parallel, concatenate, and project again — “Multi-head attention allows the model to jointly attend to information from different representation subspaces at different positions.”

4. Positional encoding — order ke bina set hai, sequence nahi

Pure attention permutation-equivariant hai agar aap positions ko explicitly na batao: tokens ka bag-of-vectors treat ho sakta hai. Language order care karti hai (“auth restart karo” ≠ “restart auth mat karo”). Isliye Transformer input embeddings mein positional information add karta hai. Original paper fixed sinusoidal encodings use karti hai — sine/cosine of different frequencies — jo model ko relative aur absolute position cues dete hain bina learned position table ke. Baad ke LLMs aksar learned positional embeddings ya relative schemes (RoPE, ALiBi) use karte hain. Simplified for intuition: aapka job yeh samajhna hai ki position signal mandatory hai; exact flavor model-family dependent hai aur CORE 203/APP 302 mein naam se wapas aayega, full Fourier analysis yahan out of scope hai.

5. Encoder vs decoder — masking is the product feature

Encoder self-attention typically bidirectional hoti hai: position i left aur right dono dekh sakti hai. Yeh BERT-style understanding models ke liye natural hai. Decoder mein, agar aap left context se next token predict kar rahe ho (language modeling), to future tokens dekhna cheating hai — training mein bhi, inference mein bhi. Isliye causal mask: softmax se pehle illegal positions par −∞ (practically ek bahut bada negative), taaki unka weight ~0 ho. Lab exactly yahi mask implement karega.

Original Transformer decoder ke paas teesra block bhi tha: encoder–decoder attention, jahan queries decoder se aate hain aur keys/values encoder output se. GPT-style LLMs mostly us cross-attention ko hata kar sirf stacked causal self-attention + feed-forward use karte hain, aur “prompt” ko bhi same token stream mein rakhte hain. Jab aap architecture diagram dekho, pehle yeh poocho: causal mask hai ya nahi? Cross-attn hai ya nahi? Uske bina boxes confuse karte hain.

Pitfall

Attention weights ko “explanation” maan lena. Weights dikate hain model ne values kahan se mix kiye, lekin yeh faithful user-facing rationale nahi hain — especially multi-layer, multi-head stacks mein. Production debugging ke liye traces + eval (PROD 401/404) pehle; attention heatmaps optional forensics hain, ship gate nahi.

6. Why Transformers beat RNNs — aur kahan bill aata hai

Teen practical reasons, bina hype ke. Pehla: parallel training. Teacher-forced training mein poori sequence ke attention scores ek saath compute ho sakte hain; RNN timesteps nahi. Doosra: short path length for long-range dependencies — incident id aur uska resolution sentence 900 tokens baad bhi ek layer mein interact kar sakte hain. Teesra: ecosystem. Once the architecture won, tooling, kernels, and pretrained weights compounded the advantage — same reason Kubernetes won ops mindshare beyond pure technical merit.

Bill side: naive attention memory aur compute sequence length ke square se badhte hain. Isliye context window marketing number sirf “kitna text” nahi, “kitna compute per call” bhi hai. APP 303 context/memory engineering isi tension ko product decisions mein badlegi (window vs RAG). Yahan aap mechanism lock kar rahe ho.

Source · optional deep dive

Harvard NLP, “The Annotated Transformer,” nlp.seas.harvard.edu/2018/04/03/attention.html — line-by-line PyTorch re-implementation of the paper. Useful if you want to see shapes in code; is course ka lab usse chhota aur NumPy-only hai.

Self-check · formative only

1. QKᵀ / √dₖ mein √dₖ scaling kyun hai?

Reveal answer

Badi dₖ par dot-product magnitudes grow karte hain; bina scaling ke softmax saturate hota hai aur gradients weak ho jaate hain. Scaling scores ko better-behaved region mein rakhta hai (Vaswani et al.).

2. Causal mask decoder-only LLM mein kya prevent karti hai?

Reveal answer

Position i ko future positions i+1…n dekhne se — training aur autoregressive generation dono mein — taaki next-token prediction leak na kare.

3. Transformers RNNs se training mein kyun better parallelize hote hain, aur kaunsa cost trade-off aata hai?

Reveal answer

Attention across a sequence can be computed without timestep-serial dependency, so GPUs chew full sequences in parallel under teacher forcing. Trade-off: naive attention is O(n²) in sequence length for compute/memory — context window is a cost knob, not only a quality knob.
