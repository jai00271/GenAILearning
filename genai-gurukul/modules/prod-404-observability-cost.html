PROD 404 · Observability & Cost Optimization

Soft budget sirf log kare — hard circuit ke bina agent raat bhar jale

Track: PROD Labs: genai-gurukul-labs/prod-404/ Offline · cost + breaker + retry storm Prereq: APP 307 agents · PROD 403 guardrails Next: PROD 405 Deploy at Scale

Production GenAI failures aksar “model dumb” nahi hoti — meters missing hoti hain. Unbounded tool loops, retry storms on 429/5xx, aur tenant-blind spend se bill explode karta hai. Is module mein observability ko cost ke saath bandhte hain: per-tenant attribution, hard circuit breakers, retry-storm detection, aur prompt/model change par cache invalidation (jo PROD 406 CI/CD pe jaati hai).

Scope: runaway agent cost; unbounded tool-call loops; retry storms; worked incident; circuit-break; cost attribution per tenant; cache invalidation when prompts/models change; Datadog/Splunk wiring. Lab offline hai — live APM required nahi.

Recall · APP 307 · Debug Lab B

APP 307 ne max_steps circuit breaker sikhaya. Debug Lab B (debug-labs/B-agent-cost-incident/) wohi muscle fail dikhata hai: soft USD budget sirf budget_warning log karta hai, halt nahi. PROD 404 hard trip + tenant meters + retry storm pe deepen karta hai.

1. Worked incident — soft budget, hard burn

Incident shape (Debug B + field stories): ReAct agent calculator (ya search) tool ko baar-baar call karta hai; soft budget cross hone pe warning events; loop continues; tokens + per-tool surcharge accumulate. RCA checklist: stop conditions diff karo — soft vs hard; model stub final answer kab emit kare; kaunse events USD increment karte hain. Fix hypothesis: hard halt on budget / max tool calls, idempotent tools, Datadog monitor on agent.usd + tool_calls.

2. Unbounded tool loops & circuit-break

Agent loop ke teen hard ceilings practically zaroori hain: max_steps (LLM turns), max_tool_calls, max_usd (ya token budget). Soft warning pehle aa sakti hai; hard trip ke baad koi tool fire nahi. Lab CircuitBreaker / run_with_breaker yahi sikhata hai — open circuit pe RuntimeError.

3. Retry storms — 429/5xx amplifiers

Client retries + provider throttling = storm. Har retry tokens + queue pressure badhata hai; multi-tenant pe noisy neighbor. Detect: sliding window mein retry count, consecutive failures, provider tag. Response: backoff + jitter, shed load, open provider circuit (PROD 405 failover se judta hai), Splunk/Datadog alert on retry_rate by provider.

Source · Datadog LLM Observability

Datadog documents LLM Observability spans/metrics for generative AI apps (tokens, latency, errors) — wire custom metrics with tenant tags for cost attribution. See docs.datadoghq.com/llm_observability. Splunk side: ingest structured JSON logs (tenant_id, tokens_in, usd, tool_calls) into an index; alert on rate spikes (docs.splunk.com — verify your org’s CIM / metric schema).

4. Cost attribution per tenant

Blended “account bill” se incident response nahi hota. Har LLM turn pe tenant_id + model + tokens_in/out meter karo; Datadog tags / Splunk fields se slice. Lab TenantCostTracker didactic rate card se USD attribute karta hai — live pricing nahi; OpenAI/Anthropic rate cards change — ship se pehle verify.

5. Cache invalidation when prompts / models change → 406

Prompt version bump ya model swap ke baad stale response caches / embedding caches galat answers serve kar sakte hain — cost “save” quality regress ban jati hai. Invalidate (or namespace) cache keys with prompt_semver + model_id. Eval flat dikhe lekin traces (tool errors, retries) worsen — woh signal CI gate mein laana PROD 406 ka kaam hai; yahan meter + alert foundation rakho.

Pitfall

Sirf monthly invoice pe cost control. Without per-tenant + per-run meters, noisy neighbor aur runaway agent dono late milte hain. Doosra: retries without jitter — thundering herd.

Portfolio-facing English · Decision stub

Treat soft budgets as alerts and hard ceilings as code paths. Attribute every LLM and tool charge to a tenant tag before you trust a shared invoice. Detect retry storms in a sliding window and open a provider circuit instead of amplifying 429s. When you change prompts or models, invalidate caches keyed by version — and fail CI when offline scores look flat but traces worsen (PROD 406).

Self-check · formative only

1. Soft budget vs hard circuit — farq?

Reveal answer

Soft = warn/log; loop chal sakta hai (Debug B). Hard = trip + stop tool/LLM calls (PROD 404 breaker).

2. Retry storm ka practical signal?

Reveal answer

Window mein zyada retries aur/or consecutive 429/5xx — provider tag ke saath alert; backoff + circuit.

3. Tenant attribution kyun?

Reveal answer

Shared invoice se noisy neighbor / runaway isolate nahi hota; meters pe tenant_id tag chahiye.

4. Prompt change → cache?

Reveal answer

Versioned keys se invalidate/namespace; warna stale answers + misleading cost savings. Trace worsen pe 406 gate.
