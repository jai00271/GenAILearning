APP 305 · RAG Deep-Dive

RAG ka asli kaam retrieve nahi — pehle documents ko sacchai se khaana

Track: APP Labs: genai-gurukul-labs/app-305/ Offline lab · fixtures + LocalEmbedder Prereq: APP 304 eval · CORE 204 embeddings Next: APP 306 vector databases

Marketing deck kehti hai “RAG = embed + top-k + prompt.” Enterprise reality alag hai: PDFs toot-ti hain, tables mid-row cut ho jaati hain, scanned pages OCR junk ban jaati hain, aur phir model confidently galat MaxDays bataata hai. Is module ka ~60% conceptual weight document ingestion pe hai — parsing, tables, OCR, messy formats, metadata, parser failure modes. Baaki: chunking, retrieval, re-ranking intuition, hybrid search, aur APP 304 metrics ko pipeline pe lagana.

LlamaIndex / LangChain jaise frameworks ek option hain — raw pipeline (parse → chunk → embed → hybrid retrieve) ke against compare karo. Framework magic ingestion mess hide nahi karti; woh sirf ownership shift karti hai.

Recall · APP 303–304 · CORE 204

APP 303 ne decide kiya: window mein thopo vs retrieve-later. APP 304 ne vocabulary di: metric / data / pass-fail + P/R/F1@k. CORE 204 ne dilaya: high cosine ≠ correct answer. APP 305 = woh retrieve-later path ko production-mess documents pe implement + measure.

1. Evaluation beat — pehle gate, phir chunk size

Har RAG change se pehle teen boxes bharo (APP 304). Is module ke convergent lab ke liye freeze:

  1. Metric (primary): macro Recall@3 on retrieved doc ids. Secondary: Precision@3, F1@3. Helpers: checkpoints/app-304 → precision_at_k / recall_at_k / f1_at_k.
  2. Data: app-305/tests/fixtures/golden.jsonl over the local fixture corpus (Okta runbook, auth health, leave-policy table extract, VPN OCR junk).
  3. Pass / fail: structure-aware chunking + hybrid retrieve pe Recall@3 ≥ 0.75 aur Precision@3 ≥ 0.25. Agar fixed-size table rows tod de aur leave query miss ho jaye — fail, vibes se “almost” mat bolo.

2. Document ingestion — first-class, not a footnote

Lab intentionally real PDF binaries avoid karti hai (CI / offline). Fixtures = parser output ke stand-ins: messy table string (.pdftxt), scanned OCR junk text, clean Markdown. Production mein tum pdfminer / pypdf / Unstructured / vendor OCR choose karoge — lekin failure modes same rehte hain.

  • PDF text layer vs scan: “PDF” ek format nahi, ek envelope hai. Digital text extract alag; scanned page pe OCR alag. Mixed docs pe silent empty extracts common hain.
  • Tables: column drift, merged cells, headers repeated mid-page, ragged rows. Fixed-size chunkers MaxDays ko LeaveType se alag kar dete hain — classic RAG miss.
  • OCR junk: glyph noise, ligatures, wrong “authoritative” instructions, kabhi stale secrets. Trust metadata + quarantine > blind embed.
  • Metadata: source path, title, page, parse_ok, ocr_suspect, tenant — retrieval filters aur citations dono ke liye.
  • Parser failure modes: empty body, partial table, exception mid-file. Fail-soft with flags; silent success with empty text = production footgun.
Sources · parsers & doc-borne security (as of August 2026)

PDF is an opaque container: text may be missing, encoded, or image-only — see the PDF Association overview of the format (pdfa.org · PDF resources) and treat “we ingested the PDF” as a claim that needs parse_ok evidence. Prompt injection via retrieved documents (not just user chat) is called out in OWASP Top 10 for LLM Applications — LLM01 Prompt Injection (genai.owasp.org · LLM01). Quarantine / provenance metadata is a mitigation pattern, not optional garnish. Perishable tooling (Unstructured, LlamaParse, Azure Document Intelligence, AWS Textract) — re-check vendor pages before you hard-lock a 2026 invoice; APIs and pricing move.

3. Chunking — fixed size vs structure-aware

Fixed-size windows (lab: word windows as a labeled stand-in for token windows — CORE 201: production should count tokens) simple hain, tables todti hain. Structure-aware prose ko window karti hai, table blocks ko intact rakhti hai, OCR ko low-trust quarantine chunk banati hai. Decision lab mein latency/cost ke saath yahi trade-off defend karna hai.

4. Retrieval, hybrid search, re-ranking

Lab embedder: checkpoints/core-204 LocalEmbedder (deterministic, offline). Modes: semantic (cosine), keyword (token overlap teaching stand-in), hybrid via Reciprocal Rank Fusion (RRF). Production mein BM25 + dense + cross-encoder reranker common hai; yahan RRF intuition enough hai.

Re-ranking intuition: first-stage retrieves broad candidates (high recall); second-stage cross-encoder / LLM reranker precision polish karti hai — cost/latency ke against. APP 306 vector DB choice se pehle yeh stage boundaries clear rakho.

LlamaIndex vs raw pipeline

LlamaIndex (and friends) ingestion + index abstractions dete hain. Use them when team velocity > custom parser control. Raw pipeline choose karo jab table/OCR policy, metadata contracts, aur eval hooks tumhari competitive edge hain. Decision lab mein likho: kya own karoge vs delegate — “we used a framework” alone rubric pe Solid nahi hai.

5. Common RAG failure modes

  • Wrong chunk boundaries (tables / lists / code)
  • OCR / parser empty or poisoned context
  • Embedding mismatch (short queries vs long chunks)
  • Keyword-only miss of paraphrases; semantic-only miss of exact IDs / numbers
  • Doc-borne prompt injection (OWASP LLM01) — retrieved text overrides policy
  • Eval leakage / golden too clean vs production mess (APP 304)
  • Top-k theatre: Recall@k flat, generation still hallucinates (need citations + refusal)

7. Decision lab — defend ingestion/chunking in English

Alag brief: genai-gurukul-labs/app-305/decision-lab/README.md. Constraints diye gaye hain (latency ≤ 1.8s p95, cost ceiling, messy corpus mix, OCR trust). Ek one-page English memo likho — portfolio artifact. Neeche full rubric full sentences mein printed hai; pass rule CORE challenge jaisi hai.

Portfolio-facing English · Pass rule

Each dimension is scored from 1 to 4. You pass the APP 305 decision lab only when no dimension is below 2 and the average across the four dimensions is at least 3.0. Revise the memo before treating the decision as portfolio-ready.

Dimension 1 — Inadequate 2 — Developing 3 — Solid 4 — Exemplary
Correctness / artifact The memo is missing, not in English, or never states a concrete ingestion and chunking choice. A memo exists but the chosen strategy is vague, internally contradictory, or omits either ingestion or chunking. A one-page English memo names a clear ingestion path and chunking strategy that fit the written constraints. The artifact would survive a design review: reproducible choices, explicit defaults, and aligned appendix.
Constraint fit Ignores latency, cost, or corpus messiness, or optimizes a vanity setup that violates the given budgets. Mentions constraints but does not connect them to the chosen parsers, OCR policy, or chunk sizes. Ties the recommendation to latency, cost/churn, and messy tables/OCR with explicit trade-offs. Shows reverse conditions (when you would switch strategies) if latency, cost, or messiness ratios change.
Evaluation evidence Relies on vibes or vendor marketing with no APP 304-style metric/data/pass-fail. Names a metric but leaves the dataset, k, or ship gate unspecified. Declares metric, golden/data slice, and pass-fail gate (for example Recall@k plus a latency ceiling). Evidence plan includes an honest failure slice (tables or OCR) and how you would re-measure after parser changes.
Production / trust awareness Ignores OCR quarantine, secret leakage in scanned pages, parser failure modes, or operational ownership. Mentions one production concern in passing without changing the design. Addresses trust (quarantine/low-trust chunks), parser failures, and who owns framework vs raw pipeline pieces. Treats ingestion as a deployable system: monitoring hooks, re-embed triggers, and security citations or policies are named.

Self-check · formative only

1. APP 305 lab ka eval beat teen boxes mein likho.

Reveal answer

Metric: macro Recall@3 (secondary P@3). Data: fixtures golden.jsonl. Pass/fail: R@3 ≥ 0.75 and P@3 ≥ 0.25 on structure-aware + hybrid.

2. Fixed chunking leave table pe kyun fail hoti hai?

Reveal answer

Windows header/rows ko alag kar deti hain — “Sick” MaxDays query ko incomplete evidence milti hai. Structure-aware table ko ek chunk mein rakhta hai.

3. Hybrid search yahan kya fuse karti hai?

Reveal answer

Semantic cosine ranking + keyword token-overlap, combined with Reciprocal Rank Fusion (RRF). Exact IDs/numbers ke liye keyword; paraphrase ke liye dense.

4. Doc-borne prompt injection ka mitigation intuition?

Reveal answer

Trust/provenance metadata, OCR quarantine, system policy that retrieved text is untrusted data (OWASP LLM01), citations + refusal — not “the chunk said so.”

5. Decision lab pass rule kya hai?

Reveal answer

Four dimensions 1–4; no dimension below 2; average ≥ 3.0. English memo; defend ingestion/chunking against given latency/cost/messiness constraints.
