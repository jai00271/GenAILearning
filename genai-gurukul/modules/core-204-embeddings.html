Embedding vectors: text ko direction banao, phir cosine se retrieve karo — aur jaano kab yeh toot-ta hai

Recall · FOUND 101 / 102

Cosine = (q·d) / (‖q‖ ‖d‖), zero-vector pe 0.0 return. Agar dono unit-normalized hain to cosine seedha dot product hai — isliye vector DBs aksar normalize-then-IP search karte hain. Yahan naya hissa yeh hai ki q aur d kahan se aate hain: embedding model (ya lab ka local stand-in) text → ℝD.

1. Embedding vector kya hai — .NET engineer ke liye

Socho aapke paas ek IT wiki hai: “VPN password reset”, “Okta MFA bypass runbook”, “cafeteria menu”. Keyword search LIKE '%VPN%' ya Lucene BM25 se kaam chal sakta hai jab vocabulary overlap ho. Semantic retrieval ka promise alag hai: user likhe “remote access credential refresh” aur phir bhi VPN article top pe aaye, chahe exact words na milen. Embedding model har string ko ek point (vector) banata hai. “Similar meaning” ≈ “nearby direction” under cosine (ya related metrics). Rank = sort by similarity.

Familiar analogy: yeh soft, learned feature hash hai — jaise aap kisi entity ko fixed-width fingerprint dekar similarity join karte ho. Elasticsearch / SQL full-text ke hard token matches ki jagah continuous scores. Analogy toot-ti hai teen jagah: (1) fingerprint yahan trained hai, aapka schema hash nahi; (2) “near” ka matlab distributional / task training pe depend karta hai, business synonym table pe nahi; (3) score calibrated probability nahi — 0.82 ka matlab “82% relevant” nahi hota bina evaluation ke (APP 304/305).

Intuition

Datadog metrics ko aap tags se filter karte ho. Embedding space soft tags ka high-dimensional soup hai — model ne training mein jo co-occurrence / contrastive pairs dekhe, wahi “tag gravity” banate hain. Isliye antonyms kabhi-kabhi qareeb aa jaate hain: “hot” aur “cold” same weather reviews mein dikhte hain, opposite meaning ke bawajood.

2. Model families — OpenAI, Cohere, open-source (Ollama / HF)

Production mein aap usually teen buckets mein se choose karte ho. Pehla: hosted API (OpenAI Embeddings, Cohere Embed) — low ops, pay-per-token, data egress policy clear honi chahiye. Doosra: self-hosted open weights (Hugging Face pe models, Ollama se local serve) — latency/cost aapke hardware pe, air-gapped possible. Teesra: hybrid — index build cloud pe, query local, ya ulat. Yeh course pehle conceptual trade-offs lock karta hai; APP 305 wiring detail dega.

OpenAI ka current embedding line text-embedding-3-small aur text-embedding-3-large hai. Official guide ke mutabiq default output length small par 1536 dimensions, large par 3072 hai, aur dimensions parameter se aap vector shorten kar sakte ho bina alag model train kiye — Matryoshka-style flexibility for storage vs quality trade-offs. Mechanics aur API shape ke liye primary docs dekho, speculative benchmark tables yahan nahi likh rahe.

Source · OpenAI Embeddings

OpenAI, “Vector embeddings” API guide, platform.openai.com/docs/guides/embeddings (also mirrored under developers.openai.com). Paraphrase: embedding models text ko numerical vectors mein map karte hain for relatedness; text-embedding-3-small / text-embedding-3-large default lengths 1536 / 3072; optional dimensions shortens vectors while aiming to preserve concept-representing properties. Create-embeddings reference documents input limits and the same dimensions field for text-embedding-3 and later.

Cohere Embed family (docs mein embed-v4.0 aur pehle multilingual v3 variants) search-oriented input_type (jaise search_query vs search_document) expose karti hai — asymmetric retrieval ke liye explicit signal. embed-v4.0 docs ke mutabiq multiple output dimensions support karta hai (256 / 512 / 1024 / 1536, default 1536 in current Embed API reference) aur strong multilingual positioning claim karta hai. Yeh “query aur doc ko same string space mein daal do” se zyada productized hai — lekin aapko phir bhi eval chahiye apne corpus pe.

Source · Cohere Embed

Cohere, Embed model docs, docs.cohere.com/docs/cohere-embed and Embed API reference docs.cohere.com/reference/embed. Paraphrase: embed-v4.0 supports selectable output_dimension values including 256, 512, 1024, and 1536 (default 1536 per API reference); semantic-search guides show distinct input_type values for documents vs queries; multilingual search is a first-class documented use case.

Open-source side pe Gurukul ka default local assumption nomic-embed-text via Ollama hai (FOUND labs README se aligned). Hugging Face model card nomic-ai/nomic-embed-text-v1.5 native dimension 768 dikhati hai, with Matryoshka truncation down to smaller sizes, aur task instruction prefixes (search_document: / search_query:) — phir se asymmetric setup. Ollama library page model ko local embed-only artifact ke tor pe document karti hai (ollama pull nomic-embed-text). Trade-off seedha hai: no per-token API bill, lekin aap RAM/CPU/GPU, model drift, aur ops khud manage karte ho.

Hugging Face model card, huggingface.co/nomic-ai/nomic-embed-text-v1.5 — paraphrase: v1.5 ships 768-D embeddings with optional Matryoshka dimensionality reduction and requires task prefixes for search/clustering/classification. 3. Dimensionality intuition

D chhota (jaise 256–384): index sasta, latency friendly, lekin fine distinctions mushkil — alag runbooks ek dusre pe collapse ho sakte hain. D bada (1536–3072): zyada capacity for nuances, lekin storage, RAM, aur brute-force scan cost badhte hain; ANN indexes (HNSW etc.) bhi memory feel karte hain. OpenAI/Cohere/Nomic teeno modern lines “shorten the vector” knobs dete hain — lekin shortened vector pe apne queries se recall measure karo; vendor blog ka MTEB number aapka incident corpus nahi hai.

Rule of thumb for engineers: pehle ek dimension pe end-to-end eval slice freeze karo, phir storage pressure aaye to officially supported truncation / dimensions parameter try karo, aur same golden queries se compare karo. Randomly slicing a vector without the vendor’s prescribed normalize-after-truncate recipe silent quality loss laa sakta hai — OpenAI guide explicitly warns about manual shortening needing renormalization.

4. When embeddings fail — honest list

Negation. “Service is healthy” aur “Service is not healthy” lexical overlap se bharpur hain. Bag-of-ngrams embedders (lab ka LocalEmbedder) inhe almost twins treat karte hain — lab isi failure ko pytest se document karti hai. Neural models better ho sakte hain, lekin short negations pe ab bhi retrieval stacks fool ho sakte hain; truth- sensitive gates ke liye sirf top-1 cosine mat use karo.

Antonyms. Distributional training similar contexts ko qareeb laati hai. “Increase replica count” vs “decrease replica count” structurally mirror images hain — embedding space kabhi-kabhi unhe neighbors bana deta hai. Agar aapka use-case polarity care karta hai (allow vs deny), embedding neighbor list ke upar explicit rules / classifiers rakho.

Tables aur code. Markdown tables, JSON blobs, stack traces — models inhe often flattened prose ki tarah dekhte hain. Column alignment, identifier scope, aur operator precedence “meaning” mein reliably nahi jaate. Practical pattern: code/tables ko alag chunk strategy (APP 305) aur kabhi-kabhi specialized encoders; pure general text embedder pe over-trust mat karo.

Out-of-domain jargon. Internal project codenames (“Project Falcon authz”) public web pe rare hote hain. General embedding models unhe galat neighborhood mein map kar sakte hain. Mitigations: domain fine-tuning / adapters (baad ke PROD modules), glossary expansion before embed, ya hybrid lexical+vector search.

Asymmetric query vs document. User ki query 8 tokens ki hoti hai; runbook 800. Simple embed-both-the-same-way kaam karta hai jab tak model / prefixes us asymmetry ke liye trained hon (Cohere input_type, Nomic search_query: / search_document:). Bina uske, long docs ka “average meaning” query se mismatch kar sakta hai — yeh chunking aur title-weighting ka asl reason hai, buzzword nahi.

Pitfall

Embedding upgrade ke baad pura index rebuild bhoolna. Vectors ek model version + dimension + prefix policy ke saath married hote hain. Naya model, naya D, ya naya instruction prefix = re-embed. Mixed index silent garbage retrieval deta hai — unit tests green reh sakte hain jab tak aapne golden queries nahi rakhe.

Self-check · formative only

1. FOUND 101 cosine aur CORE 204 embedding mein relation kya hai, aur .NET analogy kahan toot-ti hai?

Reveal answer

Cosine wahi geometry hai — embedding model sirf text → vector map provide karta hai. Analogy toot-ti hai kyunki vectors learned/distributional hain, schema hashes nahi; score calibrated “percent relevant” nahi hota bina eval ke.

2. OpenAI text-embedding-3-small default dimension kya hai, aur aap use kab shorten karenge?

Reveal answer

Official guide: default 1536. Shorten via API dimensions when storage/latency pressure ho — phir apne golden queries pe recall re-measure; vendor MTEB aapka corpus nahi.

3. Lab ka negation_failure_demo kya assert karta hai, aur production implication kya hai?

Reveal answer

Affirmative vs negated sentence ka cosine, unrelated topic se zyada hota hai under naive ngram embeddings — failure mode ko honestly document karta hai. Production mein truth-sensitive retrieval ko sirf raw embedding neighbors pe mat chhodo; hybrid checks, rerankers, ya explicit rules consider karo.
