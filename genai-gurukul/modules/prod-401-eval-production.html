1. Eval beat production mein — offline pehle, online baad mein

Offline: frozen golden / labeled trajectories; CI mein repeatable; prompt tweak se pehle baseline freeze. Online: shadow scores, human spot-checks, live disagreement queues — distribution shift pakadne ke liye. Online bina offline regression gate ke = demo confidence with production blast radius.

  • Offline gate: candidate vs baseline, max_drop hard fail.
  • Online watch: judge–human agreement, tool-error rate, traj overall.
  • Eval beat: har change ke saath metric + slice + pass-fail likho.

2. LLM-as-judge — scale with known failure modes

Strong judges humans se high agreement de sakte hain (MT-Bench / Chatbot Arena line of work — Zheng et al.), lekin position bias, verbosity bias, aur self-enhancement / self-preference documented hain. Lab ka FakeJudge in biases ko deterministic mode se dikhata hai — production judge replacement nahi, muscle memory ke liye.

Bias Symptom Mitigation habit
Position A ya B order pe winner flip Swap positions; average / require consistency
Self-preference Judge apne family ke outputs ko boost Blind IDs; cross-model judges; human audit
Rubric drift Same item, alag din alag score Frozen rubric + calibration set
Pitfall

“GPT-judge bola pass” ≠ ship. Agreement human gold se measure karo. Agar judge humans se systematically disagree kare — auto-ship band.

3. Judge disagrees with humans — what next

Yeh pehla-class failure mode hai, footnote nahi. Lab judge_human_disagreement agreement + disagreed indices + recommended_next return karti hai. Agreement < 0.8 teaching threshold pe recommended path:

  1. pause_auto_ship — candidate ko prod default mat banao.
  2. adjudicate_disagreements_with_humans — contested items pe rubric resolve.
  3. inspect_judge_rubric_and_bias — position swap / self-marker tests.
  4. recalibrate_or_replace_judge — model, prompt, ya human-only slice.
  5. expand_golden_set_on_failure_slices — jahan disagreement cluster ho.

High agreement pe bhi spot_check_sample + audit — regression mindset yeh maanti hai ke silent drift aayega.

4. Agent trajectory scoring — answer ≠ path

Final answer sahi ho sakta hai galat tool se (lucky retrieval), ya sahi tool galat args se (ticket id typo), ya extra calls se (cost + confused deputy surface). score_trajectory expected tool plan se compare karke flags set karta hai:

  • right_answer_wrong_tool — answer_ok but tool slots miss.
  • right_tool_wrong_args — tool name match, args drift.
  • has_extra_calls — plan se zyada calls jab allow_extra=False.

5. Regression gate — prompt tweak ke baad score drop

Classic incident: ek metric 2 points up, task F1 8 points down, “overall vibes better”. regression_gate(baseline, candidate, max_drop=0.05) har required metric pe absolute drop check karti hai — missing metric = fail-closed. CI annotation helper: summarize_prompt_tweak_regression.

Regression mindset

Har prompt / tool / model candidate ek build hai. Baseline freeze, diff scores, max-drop contract. “Average thoda better” ship criterion nahi — slice regressions chhupate hain.

6. Human eval — still the gold standard for contested slices

Humans expensive hain; isliye unhe targeted use karo: disagreement queue, new failure slices, rubric changes. Pure human grading har PR pe unrealistic hai — pure judge-without-audit bhi. Hybrid: judge scales, humans adjudicate, gate enforces.

Portfolio-facing English · Decision stub

Treat LLM-as-judge as a scalable approximate preference model with known position and self-preference biases. When judge–human agreement drops, pause auto-ship, adjudicate disagreements, and recalibrate before trusting scores. Score agent systems on trajectories (tool, args, extras) plus task quality, and block prompt or model candidates that exceed a frozen max-drop regression gate.
